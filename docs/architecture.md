# 架构与数据流

[项目首页](../README.md) · [使用指南](guide.md) · [测试说明](testing.md)

Xero Quest Journal 将作者定义、玩家状态和客户端显示分离。核心目标是让本地与多人游戏的完成、领奖和追踪最终由服务端决定，同时让大型列表与图编辑器减少每帧无关工作。

## 数据流

```text
任务文件 / 模板 / 作者编辑器
              |
              v
    QuestRepository + 定义校验
              |
              v
    QuestRuntime / 条件 / 奖励
        |                  |
        v                  v
  QuestProgressData    实际物品/命令等结果
        |
        v
  服务端目录与进度 Payload
        |
        v
  QuestClientInbox -> ClientQuestProgress
        |
        v
  Journal / Journey / Mailbox / HUD
```

客户端操作沿反向链路发送请求：选择追踪、提交、领奖或标记已读后，服务端校验、更新保存状态并返回结果。

## 模块职责

| 目录 | 职责 | 代表类 |
| --- | --- | --- |
| `core/model` | 任务、条件、奖励和图的结构约束 | `QuestDefinition`、`TriggerGraph`、`QuestRewardQuality` |
| `core/io` | 解析、作者保存、重载、生成和顺序 | `QuestRepository`、`QuestAuthoring`、`QuestGenerator` |
| `core/runtime` | 服务端条件、奖励、计数与场景 | `QuestRuntime`、`QuestConditions`、`QuestRewards` |
| `core/network` | 服务端定义、状态与操作协议 | `QuestNetwork`、`QuestCatalog`、`QuestClientInbox` |
| `core/mailbox` | 邮件与附件的保存、发放和删除 | `MailboxRuntime`、`MailboxData` |
| `client` | 原生界面、布局、HUD、动画、素材 | `QuestScreen`、`JourneyScreen`、`ViewportIndex` |
| `src/media` | 可选 FFmpeg 媒体实现 | `FfmpegMediaDecoder` |
| `src/smoke` | 真实客户端集成验证 | `ClientSmokeTest` 与专项回归 |

## 定义与玩家状态

任务定义包含 ID/UID、标题、类型、前置、条件、奖励、展示和可选步骤等。玩家状态包含完成记录、奖励回执、追踪、计数、锁定覆盖、每日委托与未读任务。

重要约定：

- ID 用于任务之间、章节和操作请求中的引用。
- UID 存在时可用作稳定的玩家进度身份；没有 UID 时按 ID 形成进度键。
- 定义重载不会把所有玩家历史奖励重新计算一遍。
- 多步骤任务使用当前步骤自己的条件和计数作用域。
- 客户端目录是展示快照，不等同于向远端玩家分发全部作者源码。

## 未读任务

每个世界/玩家保存 `knownTasks` 与 `newTasks`：

1. 第一次观察目录时建立基线，不把旧任务全部标新。
2. 目录变化后，将后续新出现的任务加入未读集合。
3. 进度视图通过 `newTask` 字段同步显示状态。
4. 打开任务详情后发送 `MARK_READ`，只清除当前玩家的未读状态。

未读请求使用与领奖分开的频率限制。目录观察按定义版本缓存，避免每次普通进度查询都重建一份任务集合；红点刷新只更新可见任务行，不要求重建整个列表。

`MARK_ALL_READ` 是当前玩家自己的批量已读操作，位于已有动作协议中。它不改完成、追踪、计数或领奖回执；没有未读记录时返回幂等结果。

## 物品匹配

普通物品 ID、运行时物品标签和组件精确目标使用统一条件入口。获取事件直接保留真实 `ItemStack`；现有字符串计数接口继续兼容脚本与服务器集成。

```text
拾取 / 合成 / 烧炼
         |
         v
recordItemAcquired(player, stack, amount)
         |
         v
ID 匹配 / 标签匹配 / ItemStack 组件匹配
         |
         v
当前已解锁任务与当前步骤计数
```

精确组件目标使用注册表感知的物品栈编码。它不是任意旧版 NBT 语法迁移器，也不保证忽略耐久、附魔等会变动的组件。

## 奖励与展示

`Reward` 在原有类型、目标、数量之外提供 `quality` 与 `background`。旧文件缺失这些字段时使用默认值。

| 环节 | 行为 |
| --- | --- |
| 作者编辑 | 选择品质、可选覆盖色；选择品质清除旧覆盖 |
| 任务文件 | JSON 字段或 XML/HTML 属性保存 |
| 完成 | 奖励列表冻结到玩家记录 |
| 保存 | NBT 保留品质和背景 |
| 同步 | 进度、自动领取和每日奖励协议保留样式 |
| 渲染 | 共享 34×38 卡片，支持自动品质、六档品质与背景覆盖 |

样式不会改变实际发放物品的原生属性。部分奖励会执行命令或脚本；普通展示快照不会公开这些源码。

奖励执行有逐项回执和重复领取保护，但物品变化与世界记录不是统一原子事务。该实现不承诺所有崩溃情况下的 exactly-once。

## 大型界面

![大型任务列表](images/large-task-list.png)

### 列表

`JournalListModel` 保留完整行模型，用可见范围查找选择当前视口内行。实际按钮与可见行绑定，选择和折叠状态独立保存，不因控件离开视口而丢失。

### 搜索

旧搜索逐次输入在渲染线程做全量拼音转换与嵌套组/章节扫描，虚拟化并不能解决其计算开销。现在 `JournalSearch` 分帧采集本地化字符串，`AsyncQuestSearch` 使用专用线程池缓存和检索纯文本，不在工作线程访问 Minecraft UI 或世界。

同一实例只保留最新待处理查询；120 ms 防抖，序号校验阻止过期结果，目录/语言/连接改变后失效。拼音转换器不跨 UI 线程共享。分类行模型与关联过滤也改为单次映射/分桶。详见 [ADR-0001](adr/0001-asynchronous-journal-search.md)。

### 历程与解锁图

`ViewportIndex` 是保留绘制顺序的不可变包围层次索引，用于范围查询。连线查询不能只看端点是否可见，跨越视口的连接也需要保留。

解锁图拖动时保留移动节点的覆盖层及相关连线，拖动结束后重建索引；位置编辑、连线变更和撤销重做也要保持索引一致。

### 事件图

事件图当前保留其自身节点数量约束。绘制阶段使用节点 ID 映射查找端点，避免每条边都重复扫描全部节点。它不是无限节点规模的通用图引擎。

### 不能从这里推出的结论

空间索引和虚拟化只降低一部分 UI 工作量，不等于服务端条件判定、脚本或模组物品模型也自动优化。回归记录中的可见数量不是 FPS 基准。

## 网络与版本

当前注册协议版本为 `10`，包括未读任务与奖励样式字段。目录/进度支持分块发送，作者保存使用定义版本或文件指纹检查冲突。

显示版本保持 `0.1.0`，因此兼容性不能只根据文件名判断。远端必须使用匹配的协议构建；本次工作没有完成独立服务器、所有远端状态和大型多人包的全量验收。

## 媒体拆分

核心不静态依赖全部原生媒体库。图片和基础音频保留在核心；扩展媒体经小型解码接口发现可选后端。

这样可以让任务和邮箱不依赖 FFmpeg 库是否安装，同时把核心 5 MB 限制与可选媒体包体积分开。媒体平台、编码器与释放行为仍需分别验证。

## 安全边界

- 作者文件编辑要求权限，并检查目标路径和文件冲突。
- 完成和领奖请求由服务端验证，不信任客户端进度。
- 脚本有受限接口、指令和时间预算，但不是敌对代码的通用沙箱。
- 命令/脚本行为仍应只来自服主信任的作者。
- 本仓库上传前进行了敏感文件与凭据模式检查，不代表完整安全审计或依赖漏洞认证。
