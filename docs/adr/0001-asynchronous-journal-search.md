# ADR-0001: 异步任务搜索与可复用文本索引

## 状态

已采用。针对任务过多时，输入搜索后卡顿乃至窗口未响应的问题。

## 背景

旧任务列表在渲染线程处理每次输入：逐任务收集全部搜索字段、逐字段执行 ICU 拼音转换，再反复扫描全部组与章节，最后重建列表。可见行虚拟化减少了绘制控件，但没有消除搜索前的全量计算。

任务文本可能含中文、物品组件、模组标识、组和章节信息，因此不能仅用任务标题的简单字符串匹配替代现有语义。Minecraft 的本地化、注册表与 UI 对象也不能不加区分地移到任意线程。

## 决策

1. 主线程只采集本地化后的纯文本，单帧采样预算约 2 ms / 最多 64 个任务。单个采样函数不能被强制抢占，因此这是协作式预算。
2. 使用两个低优先级守护工作线程处理纯文本索引与查询，不访问 Minecraft UI 或世界对象。
3. 每个搜索实例只保留最新待处理请求，不按输入字符累计无限任务队列。
4. 索引缓存原文、全拼、紧凑全拼和首字母；相同字段复用编译结果，仅含汉字字段调用拼音转换。
5. 拼音转换器属于当前索引构建，不与原有主线程 `QuestIcons` 转换器跨线程共享。
6. 输入防抖 120 ms。查询和目录更新使用序号校验，过期结果不应用到界面。
7. 切换目录、语言或连接时失效；关闭界面取消待处理查询。首次索引期间保留旧列表并显示搜索状态图标。
8. 组和章节关联使用映射/集合，分类行模型单次分桶，避免任务与组/章节的嵌套全表扫描。

```text
输入 -> 最新查询与防抖 -> 主线程分帧文本快照
                              |
                              v
                     工作线程缓存索引与检索
                              |
                              v
                   序号匹配 -> 主线程可视行更新
```

## 取舍

- 第一次搜索需要等待索引采样和构建，不再承诺单帧完成。
- 以额外文本索引内存换取重复搜索的低成本。
- 不在后台创建按钮、读取世界或调用原版字体渲染，避免引入线程安全问题。
- 仅加防抖但仍同步全量拼音转换不能解决大目录冻结；直接把整个屏幕重建扔到线程池也不可取。
- 暂不引入外部全文检索服务或数据库，以保留离线游戏与现有匹配语义。

## 验证

- `tools/AsyncQuestSearchCheck.java`：50,000 文档、中英文、全拼、首字母、多词交集、最新查询、目录更换、清空与取消。
- `journalOrderTest` 的 1,200 任务客户端场景：输入耗时、真实筛选结果、快速连续输入与可见行数量。
- 一键清红点单独使用已有服务端操作协议，避免搜索状态改变完成、追踪与奖励资格。
