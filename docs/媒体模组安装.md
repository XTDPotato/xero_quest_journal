# 可选媒体后端与 5 MB 主模组

## 安装

主模组 `xero_quest_journal-<版本>.jar` 控制在 **5,000,000 字节**以内，不携带 FFmpeg、JavaCPP、JavaCV（包括 Java API 与本地二进制）。任务、奖励、邮箱、编辑器、图片等功能仍在主模组中。保留 Jsoup 与 Rhino，它们分别用于文档解析与脚本执行，不能直接删除。

媒体后端全部可选。扩展编码优先顺序为游戏文件夹 FFmpeg、MediaPlayer、独立 Xero Quest Media；基础音频优先使用内置解码，不会因为安装可选后端而替换这一通道。

## FFmpeg 文件夹

把当前平台的 FFmpeg 放在游戏目录的 `ffmpeg/` 或 `config/xero_quest/ffmpeg/`：

```text
Windows: ffmpeg/ffmpeg.exe
Windows: ffmpeg/bin/ffmpeg.exe
Linux:   ffmpeg/ffmpeg
macOS:   ffmpeg/ffmpeg
```

还识别 `windows-x86_64/`、`windows-arm64/`、`linux-x86_64/`、`linux-arm64/`、`macos-x86_64/`、`macos-arm64/` 和各自的 `bin/` 子目录，以及 `windows/`、`linux/`、`macos/` 平台目录。Linux/macOS 需要可执行权限，例如 `chmod +x ffmpeg/ffmpeg`；发行包附带的动态库应保留在其要求的位置。主模组不会自动下载执行文件，也不会扫描系统 PATH。

解码通过受限 RGB/PCM 管道进行，不将 FFmpeg 可执行文件打入主 JAR。平台搜索逻辑不代表已经在每个平台执行过测试。

## MediaPlayer 1.0.1

可将 Modrinth 的 MediaPlayer 1.0.1 放进客户端 `mods/` 后重启。反射适配不复制其类或原生库，缺失时普通任务、邮件和基础音频照常工作。本次适配限定到 1.0.1 的 Windows 后端。

**已知限制：** Windows 实测可获取 MP4 的多帧图像及结束时间，但调用关闭接口后源 MP4 仍被占用，不能立即删除，因此尚未通过完整的资源释放回归。上游没有显式视频 EOF；MP4/MOV 使用 `mvhd` 时长，其他缺少可解析时长的容器可能停在最后一帧。需要稳定文件释放或其他平台支持时使用文件夹 FFmpeg。

## 独立 Xero Quest Media

需要视频或扩展音频格式时，把 `xero_quest_media-<版本>-<平台>.jar` **作为可选 NeoForge Mod 放进客户端的 `mods/`**，与同版本主模组一起使用，重启客户端。不要同时放入多个平台版本，也不要与旧版内嵌媒体库的大 JAR 混装。无需解压、改 JVM 参数或在线下载解码库；主模组不会自动下载可执行代码。

媒体 Mod 的版本、系统和 CPU 必须匹配，例如 Windows x64 使用 `windows-x86_64`，Linux ARM64 使用 `linux-arm64`。服务端不需要安装媒体 Mod。平台不匹配时，基础音频仍可尝试回退到内置解码；视频和扩展音频不能正常解码。

## 没有媒体 Mod

- 图片使用原有 ImageIO/Minecraft 渲染，不受拆分影响。
- **Ogg Vorbis** 使用 Minecraft 1.21.1 的 `JOrbisAudioStream`。`.ogg` / `.oga` 是容器名，不代表内置支持 Ogg Opus、Ogg FLAC 等其他编码；这些仍需要媒体 Mod。
- WAV、AIFF/AIF、AU/SND 使用 Java Sound，可播放其能解码/转换为 PCM 的音频（例如常见 PCM WAV），不是承诺支持这些容器中的所有压缩编码。
- 本地文件和经现有安全校验、大小限制下载的 HTTP/HTTPS 音频都可使用基础解码。扩展名不明确的网络地址在下载后识别内容。
- MP3、M4A/AAC、FLAC、Opus、视频及流式播放列表需要媒体 Mod。选择器和有效性检查共用一张能力表，不会在未安装时把扩展格式列为可用。
- 以前保存的任务不会被删掉或改写；不支持的媒体在尝试播放时提示安装可选 MediaPlayer 或使用 FFmpeg 文件夹。

## 有媒体 Mod

沿用原来的 FFmpeg 解码参数、帧抓取、图像转换、音频采样转换和主模组的播放控制。原有视频格式、扩展音频格式与网络媒体逻辑保留，没有为缩小体积裁剪编码器/解码器。本次拆分不是新增所有格式的兼容性保证；实际支持取决于上游 FFmpeg 构建。

主模组不直接链接可选库，只通过小型 `MediaDecoder` 接口与反射发现后端。可选库缺失不应导致普通界面或基础音频出现 `NoClassDefFoundError`。

## 构建

Java 21：

```powershell
# 仅主模组，check 检查 5 MB 上限及可选库未被混入
.\gradlew.bat build --no-daemon

# 主模组 + Windows x64 可选媒体 Mod，检查媒体包
.\gradlew.bat build verifyMediaAddonPackaging -Pmedia_platform=windows-x86_64 --no-daemon

# 开发客户端不带媒体 Mod，验证基础 WAV 音频
.\gradlew.bat runClient -PsmokeTest -PmediaTest --no-daemon

# 开发客户端启用可选媒体后端
.\gradlew.bat runClient -PsmokeTest -PmediaTest -PwithMediaMod --no-daemon

# 已下载 MediaPlayer 到 build/optional-mods/MediaPlayer-1.0.1.jar
.\gradlew.bat runClient -PmediaTest -PmediaPlayerTest --offline --no-daemon

# 独立 FFmpeg，参数为可执行文件路径
.\gradlew.bat runClient -PmediaTest -PlocalFfmpegTest -Plocal_ffmpeg=<可执行文件路径> --offline --no-daemon
```

可选媒体构建保留原生资源路径，将 JavaCPP、FFmpeg 各自的 Java API 与对应平台原生资源合并为同一个嵌套 JAR，避免类加载层之间找不到原生资源。重复类只保留 API 版本。JavaCV 去掉 module-info 后只在媒体 Mod 中出现。

主模组与媒体 Mod 的总下载大小仍然会超过 5 MB。5 MB 限制指主模组，不是把原生库体积消灭了。

## 本机验证范围

使用 `runClient -PmediaTest` 测试没有可选 Mod 时的原版 Vorbis、PCM WAV、文件导入、播放到 EOF、界面保存以及视频能力禁用。

使用 `runClient -PmediaTest -PpackagedMediaTest` 将实际生成的媒体 JAR 安装到隔离测试客户端，检查 NeoForge 加载、后端发现、Vorbis 和 H.264 MP4 多帧解码及 EOF。此模式不把解码依赖偷偷加入开发 classpath。

2026-10-02 之前的独立 Xero Quest Media 包已在 Windows x64 上通过实际加载与解码测试。本轮新增的 MediaPlayer 适配仍存在上述文件占用问题。其他系统、所有编码变体、网络直播及大型视频不属于这次测试覆盖范围。
